**Core mechanism (§II, Eq. 1–9; Theorem 1):** For plant ẋp = Ap·xp + Bp·u with state feedback u = K·xp rendering the closed loop (Eq. 3) asymptotically stable via Lyapunov function V(xp) = xpᵀPxp with V̇ = −xpᵀQxp (Eq. 4), the event-triggered relaxation tolerates a *slower* decay rate: V̇(xp(t)) ≤ −σ·xpᵀQxp for some σ ∈ [0,1) (Eq. 5). Defining the sample-and-hold error e(t) = xp(tk) − xp(t) for t ∈ [tk, tk+1) (this is literally our residual: the gap between the last-committed correction and the true current error), substituting into the Lyapunov derivative yields a quadratic form (Eq. 8) and the triggering condition (Eq. 9): recompute/correct exactly when zᵀ(tk)Ψz(tk) = 0 for z = [xp; e]. The paper's own worked special case (also Eq. 9's footnote) is the simple relative threshold ‖e‖² ≤ σ‖x‖² — i.e., **trigger when the accumulated error exceeds a fraction of the signal's own magnitude**, not a fixed absolute number.

**Theorem 1 (minimum inter-event time, state feedback):** for the linear plant/controller above and any σ ∈ [0,1), there exists τ* ∈ ℝ⁺ such that tk+1 − tk ≥ τ* for every k — a *formally guaranteed* nonzero minimum time between corrections, precluding Zeno behavior (infinitely many triggers in finite time). This holds for **state feedback**. §IV/V is explicit that for **output-feedback** controllers using the same relative-threshold style (as in [12], the seminal 2007 Tabuada paper), the minimum inter-event time **can be zero** — Zeno behavior — a problem identified in Donkers & Heemels (2012, cited as [26]). Donkers & Heemels's fix, described in §V.A–C (Eq. 22–34, an impulsive-system formulation), is a **mixed event-triggering mechanism**: instead of a pure relative gate, node i transmits when ‖eJᵢ(t)‖² = σᵢ‖vJᵢ(t)‖² + εᵢ (Eq. 25), combining a relative term σᵢ (scales with signal size) and a strictly-positive **absolute floor εᵢ**. §V.C states the consequence explicitly: LMI feasibility (closed-loop stability) depends only on σᵢ; **εᵢ has no effect on stability, only on event count and ultimate-bound size** — larger εᵢ means fewer events but a larger steady-state error bound, and εᵢ → 0 for all nodes risks Zeno (their own "Example 2"). §V.C names the σᵢ=0 special case explicitly as equivalent to two earlier proposals, [49] Otañez/Moyne/Tilbury "Using deadbands to reduce communication in networked control systems" and [50] Miskowicz's "send-on-delta" — **a pure fixed absolute deadband is the ε-only, σ=0 corner case of the general mixed condition.**

**Observer-based ETM (§VI.B, Eq. 36–41):** a Luenberger observer at the sensor runs on every measurement; a predictor at both sensor and controller runs on only the sporadically-transmitted subset; the trigger (Eq. 38) is ‖xˢk − xᶜk‖ > σₛ‖xˢk‖ — the observer's better estimate is sent only when it has drifted meaningfully from the predictor's coasted estimate, a relative (not absolute) threshold on *estimator disagreement*, which is structurally close to our own coasted-vs-fresh-fix comparison. The illustrative example (§VI.D, Fig. 6) quantifies the tradeoff directly: for a fixed guaranteed ℓ₂-gain bound, the model-based event-triggered scheme needs only 41 of 200 periodic transmissions (an 80% cut) versus 148 for the plain relative-threshold baseline; tightening σₛ from 0.0343 to 0.135 buys an 8% performance degradation for a 60% cut in event count (Fig. 6c/6d) — a directly quantified threshold-vs-event-count Pareto curve, not just a qualitative claim.

### 1b. NTP clock discipline — RFC 5905, "Network Time Protocol Version 4: Protocol and Algorithms Specification," June 2010

Retrieved in full (241 KB plaintext, ~6,163 lines). **Retrieval mechanics:** WebFetch's HTML-summarization pipeline repeatedly truncated the document before reaching the sections needed (Appendix A's C pseudocode and Figure 27/28's constant tables), returning "the excerpt cuts off" for four separate targeted prompts across two hosts (`rfc-editor.org`, `datatracker.ietf.org`) and two formats (`.txt`, `.html`); one fetch attempt to `people.kth.se` and one to `rfc-editor.org/rfc/rfc5905.html` additionally failed outright with a domain-verification error from the fetch tool itself. Direct `curl` of `https://www.ietf.org/rfc/rfc5905.txt` (a third host) succeeded cleanly (197 KB in under a second) and `grep`/`sed` against the local file found every constant and code path exactly.

**Clock filter algorithm (§10):** an 8-stage shift register of (θ, δ, ε, t) tuples — offset, round-trip delay, dispersion, arrival time — one per sample, oldest discarded on overflow. The selection rule is **not** "best offset" — it is **lowest round-trip delay**: "the shift register stages are copied to a temporary list and the list sorted by increasing delta [i.e., delay]." Peer dispersion is then a delay-rank-weighted sum: ε = Σᵢ εᵢ/2^(i+1) for i indexed from lowest delay (line ~2086–2096 of the retrieved text) — each successively-higher-delay sample contributes exponentially less to the trusted dispersion estimate. This is a *trust-the-least-noisy-path* heuristic, not a trust-the-newest or trust-the-median one.

**Step/slew decision and the RFC's own internal inconsistency (§11, Figure 27, Appendix A.5.5.6):** the parameter table (Figure 27) lists `STEPT | 125 | step threshold (.125 s)`, while the reference-implementation C code in Appendix A.5.5.6 defines `#define STEPT .128 /* step threshold (s) */` — **125 ms in the prose table, 128 ms in the pseudocode**, an unresolved discrepancy inside the RFC text itself, worth flagging rather than silently picking one. Alongside STEPT: `WATCH | 900` (stepout threshold, seconds) and `PANICT | 1000` (panic threshold, seconds). The decision logic (§11 prose, Appendix A.5.5.6 code): PANIC if |offset| > PANICT (process exits — offset too implausible to act on at all); **STEP** if offset is under PANICT but over STEPT — the clock is *stepped* to the correct value directly, but "since this means all peer data have been invalidated, all associations MUST be reset and the client begins as at initial start" (§11 prose) — i.e., a step is a **full state wipe**, not a scoped correction; **ADJ** (slew) if offset is under STEPT — a smooth adjustment via the PLL/FLL feedback loop, no state reset.

**The state machine's built-in "wait for a second occurrence" logic (Figure 28, Appendix A.5.5.6 pseudocode):** states NSET/FSET/SPIK/FREQ/SYNC. From steady-state SYNC, a single sample exceeding STEPT does **not** step the clock — it transitions to SPIK and returns SLEW (i.e., the outlier is provisionally ignored). Only if the offset **stays** above STEPT for longer than the WATCH stepout window (900 s) does the code fall through to `step_time()`. The code comment is explicit: "In S_SPIK state, the stepout threshold has expired and the phase is still above the step threshold. Note that **a single spike greater than the step threshold is always suppressed**, even at the longer poll intervals." This is NTP's version of "a real jump repeats, noise doesn't" — structurally identical in spirit to our own `outlier_gate_ms`/`outlier_pending_` two-hypothesis gate in `estimator.h`, but formalized as an explicit state machine with a **persistence timer** (WATCH) rather than a simple "next sample" check.

**Popcorn spike suppressor (Appendix A.5.5, clock_filter code comment, ~line 4780):** a second, independent, faster-timescale filter, separate from the STEP/SLEW state machine above: "Compare the difference between the last and current offsets to the current jitter. If greater than SGATE (3) and if the interval since the last offset is less than twice the system poll interval, dump the spike." SGATE = 3 — the gate is **jitter-relative** (3× the running jitter estimate), not an absolute millisecond figure, and it only fires for spikes close together in time (within 2 poll intervals); a large jump that occurs after a longer gap is *not* suppressed by this filter (it falls to the STEP/SLEW machine instead). Two independent gates at two different timescales, one relative-to-noise-floor and time-windowed, one absolute-magnitude and persistence-windowed.

### 1c. Data association — Bar-Shalom & Tse (1975) and Reid (1979) unreachable; Michael Grinberg, "Data Association for Multi-Target-Tracking," KIT Vision and Fusion Laboratory Technical Report IES-20xx-xx

**Both requested primaries are unreachable.** Bar-Shalom & Tse, "Tracking in a Cluttered Environment with Probabilistic Data Association," *Automatica* 11 (1975), 451–460, is paywalled (ACM/Elsevier, no free full text found via ResearchGate, Academia.edu, or Semantic Scholar — all returned abstract/metadata pages only). Reid, "An Algorithm for Tracking Multiple Targets," *IEEE Trans. Automatic Control* AC-24 (1979), 843–854, is likewise paywalled with no free copy located.

**Substitute actually read in full: Michael Grinberg (Karlsruhe Institute of Technology, Vision and Fusion Laboratory), "Data Association for Multi-Target-Tracking," 22 pp., a genuine technical report (not a slide deck or blog post) that **re-derives** the PDA equations from Bar-Shalom's own formulation with full citation ([BST75] = Bar-Shalom & Tse 1975, [BS78] = Bar-Shalom 1978, [Rei79] = Reid 1979), i.e., this is explicitly a *secondary* treatment quoting the primary equations, clearly labeled as such throughout this section. **Retrieval mechanics:** WebFetch reported the PDF as "corrupted/improperly encoded binary" and could not extract text; the same fetch call's raw PDF bytes were cached to a local tool-result path, and Read on that cached path parsed all 22 pages cleanly — identical recovery pattern to the sibling doc's Wang/Gururani retrievals.

**PDA gating equation (§3.2, Eq. 3.1–3.2):** for track x with predicted measurement density N(ẑᵏₓ, PᵡZₖZₖ), a hyper-ellipsoidal **validation gate** Γᵡₖ(γ) = {z : (z−ẑᵏₓ)ᵀ(PᵡZₖZₖ)⁻¹(z−ẑᵏₓ) ≤ γ} (Eq. 3.2) admits a candidate measurement iff its Mahalanobis distance is under γ; because innovations are Gaussian, (Z−ẑᵏₓ)ᵀ(PᵡZₖZₖ)⁻¹(Z−ẑᵏₓ) ~ χ²(nz), so a constant gate probability P_G is obtained by choosing γ = χ²(nz, P_G) from chi-square quantile tables — **the gate threshold is derived from a target false-exclusion probability, not picked arbitrarily.** This is the formal generalization of a fixed innovation gate like `outlier_gate_ms`: γ is sized to the *current* posterior covariance (which changes over time), not to a single hand-set millisecond constant.

**PDA soft association (§3.2, Eq. 3.3–3.6):** every measurement zₖ,ⱼ inside the gate gets its own hypothesis θˣ→ᶻʲ ("this is the real one, the other mₖ−1 in-gate measurements are clutter"); a null hypothesis θˣ→ᶻ⁰ covers "none of them are real." Bayes' rule over a clutter model (Poisson, parametric, or uniform, non-parametric — Eq. 3.3–3.5) yields per-hypothesis weights β. The composite state update (**Eq. 3.6**) is x̂ₖ = x̂⁻ₖ + Kₖ·Σⱼβˣ→ᶻʲ·z̃ˣₖ,ⱼ — instead of committing to one measurement, the Kalman update is applied against a **probability-weighted blend of every in-gate innovation.** The posterior covariance (§3.2, following Eq. 3.6) is correspondingly inflated by a spread term P̃ₖ that grows with how much the in-gate candidates disagree with each other — **soft, reversible association with an explicit uncertainty penalty for ambiguity**, versus a hard, single-winner pick.

**Multi-scan/MHT framing (§3, intro to §3.1):** single-scan algorithms (NN, GNN, PDA) "consider only data of the current frame," while multi-scan (MHT, citing [Rei79]) "simultaneously evaluate multiple hypotheses maintaining them throughout several frames in anticipation that the new data will allow to resolve emerging conflicts" — MHT defers commitment *across time*, keeping a small tree of candidate track histories alive rather than collapsing every frame to one blended estimate the way PDA does.

**§4 (Conclusion) names a further refinement not requested but directly relevant: Integrated PDA (IPDA)**, Mušicki & Evans [MES94, ME02], which augments PDA with an explicit **track-existence probability**, modeled as a two-state Markov chain ("track exists" / "track does not exist"), integrated directly into the association-probability computation rather than assumed as given.

### 1d. Dual control / active probing — Feldbaum (1960–61) unreachable; Björn Wittenmark, "Adaptive Dual Control," EOLSS *Control Systems, Robotics and Automation*, Vol. X — **partially retrieved (6 of 11 pages; remainder paywalled)**

**Feldbaum's four original 1960–61 papers ("Dual Control Theory I–IV," *Automation and Remote Control*, translated from Russian) are unreachable** — no free digitized copy of this pre-internet translated Soviet-era journal was found; this is stated as fact, not inferred from a single failed search.

**Wittenmark's EOLSS chapter — genuinely partial.** EOLSS ("Encyclopedia of Life Support Systems") sample chapters expose roughly half their content for free and paywall the rest behind a "click here" link; here that meant pp. 1–6 of 11 (through §2, "Stochastic Adaptive Control," and its worked example) were retrieved cleanly via direct `curl` (no WebFetch garbling this time — the file downloaded and read without incident), while §3 "Optimal Dual Controllers," §4 "Suboptimal Dual Controllers" (specifically §4.1 "Perturbation Signals," which is exactly the concrete probing-magnitude formulas this research needs), and §5 "When To Use Dual Control?" are **not accessible** — only their section titles, visible in the table of contents, and the bibliography (which is not paywalled) survived. This gap is treated honestly in §4 below rather than papered over.

**Feldbaum's dual-goal framing (§1, quoted from the retrieved text):** "the controller must have dual goals. First, the controller must control the process as well as possible. Second, the controller must inject a probing signal or perturbation to get more information about the process. By gaining more process information, better control can be achieved in future time." The formal solution is a functional (Bellman) equation from dynamic programming, "intractable from a numerical point of view" — hence the entire suboptimal-dual-control literature exists to approximate it.

**Certainty equivalence vs. cautious control (§2, Eq. 5–11, the retrieved worked example):** for a discrete integrator with drifting unknown gain θ(k+1) = φθ(k) + ν(k) (Eq. 8–9), the certainty-equivalence controller (Eq. 10) is u(k) = −y(k)/θ̂(k+1) — plug in the point estimate and control as if it were exact. The **cautious controller** (Eq. 11) is u(k) = −θ̂(k+1)·y(k) / [θ̂²(k+1) + pθ(k+1)] — the same numerator, but the denominator is inflated by the parameter-uncertainty variance pθ, **shrinking the control gain as uncertainty grows.** Both are explicitly labeled **non-dual**: "The certainty equivalence and the cautious controllers do not deliberately take any measure to improve the information about the unknown process parameters. They are thus non-dual adaptive controllers. **The learning is 'accidental' or 'passive' — there is no intentional probing signal introduced.**"

**The turn-off phenomenon (§2, prose following Eq. 7):** "With small control signals, less information will be gained about the process and the parameter uncertainties may increase, and even smaller control signals will be generated. This vicious circle leads to **turn-off of the control**." A cautious (non-dual) controller, faced with rising uncertainty, responds by acting *less*, which starves the estimator of exactly the excitation it needs to reduce that uncertainty — a self-reinforcing silence.

**Substitute — Hang's EOLSS chapter, partial (through §2 of 6 sections).** Same EOLSS access pattern as Wittenmark: pp. 1–6 of 18 retrieved via direct `curl` (clean, no garbling), covering §1 "Introduction" and §2 "Controller design" in full; §3 "Performance comparison," §4 "Modification for high order systems," §5 "Modification for rapid load rejection," and §6 "Modifications for open-loop unstable systems" are paywalled beyond the visible table of contents. The bibliography (not paywalled) is the one place several further-relevant papers are named — see below.

**Structure and design equations (§1, Fig. 1; §2, Eq. 1–9):** for G₁(s) = kₚe^(−sL)/(1+sτ) (Eq. 1), the Smith predictor's inner loop runs the *undelayed* process model to produce a fast-feedback prediction yₐ, driving a simply-tuned PI controller C₁(s) = kc1(1 + 1/(sTi1)) (Eq. 2), while the outer loop corrects for load disturbance and modeling error via the predictor error ep = (measured y) − (predicted y with the model's own delay applied). For the first-order case, matching a desired closed-loop time constant Tm yields Ti1 = τ (Eq. 4) and kc1 = τ/(kₚTm) (Eq. 5), with Tm typically specified as 0.2–1.0× the open-loop time constant τ.

**The delay-mismatch resonance result (§2, Fig. 2, Eq. 10) — the specific mechanism the brief asked for.** If the true process is G₁(s) = G(s)e^(−sL) but the predictor's internal model uses L+ΔL instead of the true L, the mismatched Smith predictor is equivalent to a *different*, larger closed loop with an extra feedback path H(s) around it, where

**H(s) = 1 + e^(−s(L+ΔL)) − e^(−sL)** (Eq. 10)

— not a small, graceful bias term, but a transfer function with **resonance peaks at specific frequencies** determined by ΔL. The stated design guidance: "the controller gain should then be suitably adjusted to ensure that the closed-loop transfer function without mismatch has sufficient attenuation, say **greater than 6 dB**, at the frequencies where H(jω) has resonance peaks." I.e., a delay/rate-estimate mismatch under a Smith-predictor-style architecture doesn't just make the correction slightly wrong — it can excite an internal loop that **rings**, and the only defense in this framework is designing the *nominal* (no-mismatch) loop with margin specifically at the mismatch-induced resonance frequencies, not just generic robustness everywhere.

**Bibliography-only leads (not retrieved, named because Hang's own annotations single them out as directly relevant to the *integrator* case — which is our case, since playback position is literally ∫rate dt):** Åström, Hang & Lim (1994), *IEEE TAC* 39(2), 343–345, "allows load disturbance response to be designed independent of the setpoint response" for "a process with an integrator and long dead-time"; Normey-Rico & Camacho (1999), *IEEE TAC* 44(8), 1597–1603, "uses a mismatched model to eliminate the steady-state error for the Smith predictor control of a process containing an integrator." ### 1f. Media playout synchronization — RFC 7272, "Inter-Destination Media Synchronization (IDMS) Using the RTP Control Protocol (RTCP)," June 2014; Liang, Färber & Girod, "Adaptive Playout Scheduling and Loss Concealment for Voice Communication Over IP Networks," *IEEE Trans. **RFC 7272 retrieved in full** (43 KB plaintext, 1,291 lines) via direct `curl` of `rfc-editor.org/rfc/rfc7272.txt` after WebFetch's HTML pipeline returned only fragmentary, hedged summaries across two separate targeted prompts.

**The mechanism, and the one part that is step-compatible (§4, tutorial walkthrough, non-normative but concrete):** a Media Synchronization Application Server "calculates a reference client from the received RTCP XR IDMS Report Blocks (e.g., by selecting the **most lagged** client as the reference for IDMS)" and distributes that target playout point to every client via a new RTCP IDMS Settings Packet (§7, carrying 64-bit NTP-format Packet-Received and Packet-Presented timestamps per RFC 5905's own timestamp format, per §6). **Stated accuracy requirement (§8):** "For social TV, synchronization accuracy should be achieved on the order of **hundreds of milliseconds**. In that case, correct use of NTP on receivers will in most situations achieve the required accuracy." For higher-accuracy use cases the RFC recommends a local NTP server or a "more accurate clock synchronization mechanism" (implicitly PTP-class). This is a directly citable, numeric perceptual-tolerance anchor from a standards document, not an informal guess.

**Liang, Färber & Girod, retrieved in full** (12 pp., all figures/tables legible) via the same WebFetch-garbled-then-Read-cached-PDF recovery pattern as source 1c. This is not directly about clock sync at all — it is VoIP jitter-buffer playout scheduling — but it is the concrete, quantified "adaptive playout" literature the brief asked for.

**The core mechanism (§II–IV) assumes signal-level access we don't have.** Their headline result (Algorithm 3, "within-talkspurt adjustment") continuously micro-stretches/compresses individual voice packets via single-packet WSOLA (Waveform Similarity Overlap-Add, §III.A, Fig. 3) so that **the playout clock itself can be adjusted smoothly, packet by packet, without an audible discontinuity** — this is a continuous-actuation mechanism realized by editing the audio signal itself, not by a hard step. Table III (subjective DCR listening test) shows this smoothing is genuinely inaudible-to-barely-audible even at extreme scaling ratios (35–230% of nominal packet length, up to 24% of packets scaled, DMOS scores 4.5–4.7 out of 5, versus 4.8 for an unmodified null-pair control). Table IV/§VII shows the resulting system-level gain: for a fixed buffering delay, burst loss rate drops from 12% to 1% and mean opinion score improves by roughly one full point (fair→good) versus a between-talkspurt-only (coarser-grained) adaptation baseline.

**What transfers regardless of signal access — the adaptive threshold (§IV.A, Eq. 5–8).** The playout deadline is not a fixed constant; it is derived from the **order statistics of the last w packets' measured delays**: sorted delays D¹≤...≤Dʷ, extended with an estimated worst-case tail D^(w+1) = D^w + 2·s_dn (Eq. 7, sdn = sample standard deviation of recent delay) to avoid trusting a too-small, too-optimistic recent sample. Given a user-specified acceptable loss rate ε̂ₗ, the deadline is interpolated between order statistics to hit that target (Eq. 8) — **the threshold widens or narrows automatically with recently observed scatter**, rather than being one hand-tuned millisecond constant for all conditions. §IV.B, "Adaptation to Delay Spikes," adds a **rapid-adaptation mode**: on detecting a sudden delay spike, the first spike sample is discarded outright, and the estimator switches to directly tracking the new level rather than waiting for the order-statistics window to catch up, reverting to normal mode once delays return to pre-spike levels — a provisional-then-confirmed state transition structurally parallel to NTP's SPIK/FREQ states (source 1b) from an entirely independent literature.

## 2. Mechanism-by-problem mapping

### (i) Constant residuals stuck in the deadband — Vienna's ~300 ms triple-agreement (engine 281/mic 314/ear ~250), Dreams's constant ~285 ms echo, 0 corrections

**What applies, concretely:**

- **Liang et al.'s order-statistics-adaptive threshold (§IV.A, Eq. 5–8, source 1f)** is the closest structural fit: replace the single fixed `deadband_ms` (350 ms as shipped, `android/app/src/main/java/com/jointheparty/app/session/SessionGraph.kt`'s `ENGINE_DEADBAND_MS`; 25 ms core default in `EstimatorConfig`) with a value derived from the **recent scatter of committed residuals**. A track like Vienna, where three independent instruments (engine, mic, ear) agree to within ~65 ms of each other and stay that way for the whole cycle, has a *low-scatter* residual history — Liang's Eq. 5–8 logic would let its effective threshold shrink over time, eventually admitting a correction that a fixed 350 ms deadband can never trigger. **Concretely:** add a fixed-size ring buffer of the last N committed-fix residuals to `SyncEstimator` (a new field alongside `in_deadband_streak_`, e.g. `residual_history_[8]`), and compute an effective deadband each `on_estimate` call as a function of that buffer's spread — this lives in `estimator.h` (data) and `policy.h` (the function of it that becomes the actual gate), not `lag_window.h`.
- **Heemels et al.'s mixed relative+absolute threshold (Eq. 25, source 1a)** supplies the *formal* reason this is safe: as long as the absolute floor ε (our existing `deadband_ms`) stays strictly positive, the LMI-feasibility/stability guarantee (§V.C) is untouched by shrinking the relative/scatter-dependent component — only the ultimate-bound size and event count change. This licenses treating the *floor* as fixed (never shrink `deadband_ms` itself to zero — the field-test-8 deadband-150 experiment already showed a uniformly-lowered floor churns) while letting a **separate, corroboration-scaled term** do the actual shrinking. New field: `PolicyConfig::deadband_relative_scale`, combined with `deadband_ms` in `CorrectionPolicy::on_estimate`.
- **NTP's persistence-before-acting pattern (Figure 28, WATCH=900s stepout, source 1b)** supplies the other missing half: a residual that is corroborated (three instruments agree) and *persists* beyond a stepout window should eventually be treated as real evidence of a genuine offset, not indefinitely re-classified as "inside the noise floor." **Concretely:** a new persistence timer in `policy.h`, distinct from `settle_ns` (which suppresses measurements *right after* a seek) — this one accumulates while a stable, sub-deadband, but non-zero residual is repeatedly observed, and eventually authorizes a correction even though no single fix ever crossed the raw deadband.

### (ii) Deadband-lowering causes beat-comb correction churn — 8 corrections in 77 s chasing the song's own beat comb into an on-beat-but-3-beats-late hole

**What applies, concretely:**

- **PDA's soft, gate-sized-by-covariance association (Grinberg §3.2, Eq. 3.2/3.6, source 1c)** is the direct generalization of the sibling doc's already-recommended multi-hypothesis Kalman bank (`research-offset-disambiguation.md` §4 item 3) — **this research adds the gating/pruning/confirmation rule that doc left unspecified.** Concretely: when `lag_window.h`'s comb-flatness extension (per the sibling doc) or ACRCloud returns multiple plausible offset candidates at beat-period spacing, instantiate a small bank of `SyncEstimator` copies (2–3, one per candidate), and gate each subsequent fix against each hypothesis's **own posterior covariance** using Eq. 3.2's Mahalanobis test (γ from a χ² quantile table for a chosen gate probability) rather than the single fixed `outlier_gate_ms=1200.0`/`outlier_gate_max_p00=10000.0` pair currently hardcoded in `EstimatorConfig`. This is a strict generalization: the existing `outlier_gate_ms` is already an ad hoc 2-hypothesis special case (per its own comment, "a SECOND consecutive outlier is accepted") — Eq. 3.2 turns that into a principled, covariance-scaled gate applicable to N hypotheses, not just 2.
- **IPDA's track-existence probability (Grinberg §4, Mušicki & Evans, source 1c)** supplies the pruning rule for the bank: give each hypothesis-estimator an existence-probability state (a 2-state Markov chain, "exists"/"doesn't exist," updated alongside the usual Kalman update) that decays when a hypothesis stops being corroborated — reusing `conf_age_tau_s`'s existing age-decay pattern in `estimator.h` but applied per-hypothesis, so a hypothesis whose existence-probability falls below threshold is dropped from the bank rather than continuing to compete.
- **Heemels et al.'s Theorem 1 minimum-inter-event-time guarantee (source 1a) does *not* directly solve this, and that gap should be stated honestly.** Theorem 1's guarantee is derived for **state feedback with a trustworthy triggering variable** — it guarantees the *actuator* can't be driven Zeno by the *controller's own logic*. It says nothing about a case where the **triggering variable itself is multimodal and untrustworthy** (a comb of nearly-equal-strength candidate offsets), which is exactly our failure: `settle_ns=3s` already enforces a nonzero minimum time between our seeks, and the churn still happened, because each individual comb-tooth fix looked locally like a legitimate, confirmed measurement. The fix has to be at the data-association layer (PDA/IPDA above), not the minimum-inter-event-time layer, which we already have.

### (iii) Self-match after room discontinuity — perfect 1:1 continuity, constant zEnd, engine self-confirms "LOCKED"

**What applies, concretely, and what doesn't:**

- **None of the six literatures solve source discrimination directly**, and it's worth being precise about *why not*, rather than just noting a gap. NTP's popcorn spike suppressor (SGATE, source 1b) is a magnitude/timing gate on a *single instrument's own noise*, not a test of *which physical source* an instrument is listening to — irrelevant here. PDA/IPDA's clutter model (source 1c) explicitly assumes clutter measurements are **independently, identically, uniformly distributed** over the gating region (Grinberg §3.2, "clutter measurements are assumed to be independent from the correct measurement... independent and identically distributed over the whole gating region") — our self-match "clutter" is neither independent (it is *caused by* our own last seek) nor uniformly distributed (it advances in perfect 1:1 lockstep, with an anomalously *constant* zEnd of ~121–145 ms versus real fixes' 217–562 ms jitter, per field-test-8-results.md) — it is **the single most PDA-model-violating kind of clutter possible**: structured, self-correlated, and systematically better-fitting than the true signal. Applying PDA's math here would not merely be unhelpful, it would be actively wrong, because PDA's soft-blend (Eq. 3.6) would give the anomalously clean, low-jitter self-match candidate *higher* weight than a genuinely noisy real fix, compounding rather than fixing the failure. This needs to be flagged, not glossed over: **do not naively route the self-match problem through the PDA/hypothesis-bank machinery recommended for (ii)** — the bank assumes all hypotheses are honest measurements of the same underlying signal at different candidate lags, which is false here (one "hypothesis" is not measuring the target signal at all).
- **This research's one genuine, non-duplicative contribution to (iii) is formal grounding for the *probe-scheduling decision*, not a new detection mechanism.** The sibling doc (`research-offset-disambiguation.md` §2b) already proposes the buildable fix — a deliberate, known perturbation (micro-seek/pause) whose signature only our own audio carries, composing with the already-ticketed CTL-01 referee-validity sentinel. Wittenmark/Feldbaum's dual-control framing (source 1d) supplies the missing **when**: fire the active probe precisely when the system is in Wittenmark's "turn-off" condition — confidence has decayed (§2's cautious-controller pattern, mirrored by our own `min_confidence_to_correct=0.35f` gate in `policy.h`) **and** the passive fix stream has stopped correcting that decay on its own. That is a formal, literature-grounded trigger condition where the sibling doc left the probe-timing question open ("a deliberate, known perturbation" — timing unspecified).

## 3. The step-only constraint — every borrowed mechanism, assessed against "no slew, every actuation is audible"

The plant is commanded only by discrete SEEKS with 100–500 ms variable execution latency; there is no analog of a continuous playback-rate control (Spotify App Remote is seek-only). Every mechanism above is checked against this explicitly.

- **NTP's ADJ/slew branch (source 1b) assumes continuous rate control and does not apply, full stop.** `adjtime()`'s entire purpose is to slew the *rate* of a free-running oscillator smoothly toward the correct phase — there is no equivalent operation available to us (no "play 1.001× speed for the next 10 s"). What *does* transfer is NTP's **decision logic**, not its mechanism: the persistence-plus-magnitude gate (STEPT + WATCH) that decides *whether and when* to fire the heavier STEP action. Since we are *always* in "step" mode (every actuation is a seek), the useful borrowed idea is narrower than the full state machine: adopt the magnitude+persistence *gating discipline*, but explicitly **do not** adopt NTP's STEP consequence of "reset all peer associations" wholesale — that is calibrated for a full clock resync where all history really is suspect; for us, a single confirmed large-offset correction should reset the *offending* estimator state (or a targeted subset), not wipe convergence state, confidence, and drift estimate for the whole filter, which would be a much bigger perceptual and re-acquisition cost than NTP's designers were budgeting for.
- **Heemels et al.'s event-triggered framework (source 1a) is actuation-agnostic by design and largely applies cleanly.** §II's own formalization is explicitly sample-and-hold (Eq. 6, u(t) = u(tk) held constant between triggers) — i.e., the framework was built assuming a *piecewise-constant* actuator signal from the start, which is structurally close to "hold position, then jump." The one place a caveat is needed: the minimum-attention/self-triggered results (§III, Theorems 2–3) derive their stability guarantees assuming the controller can choose the **actuation value** freely and *precisely* at each trigger instant to drive the Lyapunov function down by a known amount. Our "actuation value" (a seek target) lands with 100–500 ms of its own execution-timing uncertainty (`seek_exec_var_ms2=2500.0` injected variance per seek in `EstimatorConfig`) — the trigger-timing math transfers; the assumption that the chosen action lands exactly where computed does not, and any adopted trigger condition needs its own margin for landing uncertainty on top of the measurement uncertainty Heemels et al. model.
- **PDA's soft-blend update (Eq. 3.6, source 1c) is actuation-agnostic in a genuinely clean way — no adaptation needed.** Radar tracking never "actuates" the target being tracked at all; PDA blends *estimates*, and the blending happens entirely inside estimator-state space (a weighted sum of Kalman corrections), never touching how or when an actuator fires. The step-only constraint is a complete non-issue for this specific mechanism: we can maintain N smoothly-blended internal hypotheses with zero audible cost, and only the eventual *hypothesis-bank collapse-to-one* needs to trigger an audible seek.
- **Dual control's probing action (source 1d) changes character entirely under the step-only constraint, and this is the most important adaptation in this whole section.** Classical dual control (Feldbaum's framing, Wittenmark's Eq. 3–4 loss function) models probing cost as a smoothly-increasing, typically *quadratic* term in the control-signal energy — dither a little more, pay a little more, on a continuous scale. For us, a probe is a discrete seek or pause: **there is no smooth dial between "no probe" and "one probe" — the cost is closer to a near-fixed, binary penalty per probe** (one audible glitch), not a term that shrinks gracefully as probe amplitude shrinks. This breaks the implicit cost model every one of Wittenmark's suboptimal-dual-control approximations is built on (§4's titles — "Perturbation Signals," "Constrained One-Step-Ahead Minimization" — all presuppose a continuously-adjustable probe magnitude, though the paywalled §4.1–4.5 could not be checked to confirm the exact formulas). **The practical consequence:** treat "shall we probe at all" as a rare, discrete, gated decision (fire at most once per confidence-decay episode, per §2(iii) above) rather than attempting to port any continuous dither-magnitude formula from this literature — there isn't one that fits our cost structure among what was retrieved.
- **Smith predictor (source 1e): the mechanism does not apply, but the specific lesson (H(s) resonance under delay mismatch, Eq. 10) does, cleanly, because it is a property of the feedback structure, not of continuous actuation.** We would never implement a literal Smith predictor — there is no continuous control signal for an inner-loop model to filter. But Eq. 10's finding — that an *uncorrected delay/rate-estimate mismatch produces an internal resonant loop, not just a bounded bias* — translates directly to our `command_latency_ms` online adaptation (`latency_adapt_gain=0.7` in `PolicyConfig`, learned from "the first post-settle estimate after each seek reveals the landing bias"): **field-test-8's 1259 ms overshoot from a single conf-0.74 fix is exactly the failure mode this equation predicts** — a latency/drift model error doesn't just miss by a fixed amount, it can seed an oscillating correction sequence. The existing `latency_adapt_clamp_ms=500.0` (bounding how much a single fix can move the learned latency) is already doing informal duty as the "sufficient attenuation" margin Hang's guidance calls for — worth keeping and possibly tightening, not removing.
- **RFC 7272's two options split cleanly on this axis (source 1f): the rate-slew option assumes continuous playback-rate control (does not apply, same reason as NTP); the pause-then-catch-up option is entirely step-compatible** and, notably, is structurally already present in this codebase for a different purpose (the end-of-track pause guardian). No adaptation needed here — it is simply the one branch of the RFC's own tutorial example that was already the right shape for us.
- **Liang/Färber/Girod's WSOLA time-scale modification (source 1f) does not apply, for a *different* reason than NTP's slew.** It's not that we lack a rate-control API — it's that the mechanism requires **PCM access to the audio being played**, to elastically stretch or compress it sample-by-sample. We have no such access to Spotify's rendered output; this is the identical "phantom reference" problem the sibling doc's self-fingerprinting recommendation already had to work around (`research-offset-disambiguation.md` §2b's correction, `sc_push_reference`). What *does* transfer regardless — because it operates purely on delay measurements, never on the audio signal itself — is the order-statistics adaptive-threshold idea (§IV.A, Eq. 5–8), used in §2(i) above.

## 4. What remains unsolved

1. **No source in this research models a cost structure matching ours: discrete, near-fixed-penalty-per-actuation control effort.** Classical dual control (Feldbaum/Wittenmark) assumes smoothly-scalable probing cost; NTP and RFC 7272's slew options assume free, continuous, silent actuation; PDA/MHT never actuate anything. None of the six literatures retrieved give a formal answer to "how much is one audible glitch worth, and how does that trade off against estimator uncertainty." The composite design in §5 below can specify *when* to probe (a gated, rare decision) but not a literature-derived *optimal* probe magnitude or frequency — that remains a heuristic pending either new theory or field-test-driven tuning.
2. **Wittenmark's actual probing-signal design formulas (§4.1–4.5) were never retrieved — genuinely paywalled, not merely unread.** Everything in §1d/§3 above about dual control is grounded in §1–2 of the chapter (the problem framing and the certainty-equivalence/cautious-controller distinction); the concrete suboptimal-dual-controller mechanics this research was tasked to find are behind an EOLSS paywall this session could not get past. This is a real gap in the research, not a design choice.
3. **PDA/IPDA's clutter-independence assumption is actively violated by our hardest failure mode (self-match), and none of the retrieved sources offer a data-association technique for self-correlated, action-caused "clutter."** §2(iii) above is explicit that applying PDA's math to this case would make things worse, not better. This is not a minor caveat — it means the single most-cited data-association literature in this research (PDA/JPDA/IPDA) is the *wrong tool* for the codebase's most severe measured failure, and that failure stays entirely in the domain of the already-ticketed CTL-01/CTL-02 and the sibling doc's self-fingerprint proposal.
4. **Nothing in any of the six sources tells us whether a small, cross-instrument-corroborated, stable residual (Vienna's engine 281 ms / mic 314 ms / ear ~250 ms) is a real, correctable sync error or a legitimate, uncorrectable acoustic-path floor** (AEC latency, speaker-to-mic transit time, codec buffering). Liang et al.'s order statistics adapt to *scatter within one instrument's own history*; none of the six sources model cross-instrument *agreement* as a signal, and none model an acoustic transmission path at all — the same gap `research-offset-disambiguation.md` §3 already noted for its own two sources. This remains the central open question behind failure mode (i), and this research does not close it.
5. **No beat/tempo prior for seeding comb-hypothesis candidates.** Same gap the sibling doc already flagged in its §2a/§3 — nothing in event-triggered control, PDA/MHT, dual control, NTP, Smith-predictor theory, or media-sync literature supplies a rhythm model. A multi-hypothesis bank per §2(ii) above still needs an external source of candidate offset spacing.
6. **The RFC 5905 STEPT discrepancy (125 ms vs. 128 ms, §1b) was never resolved to a single authoritative value** — both numbers appear in the same standards document, and no errata was checked for this specific research pass. Anyone implementing NTP-style persistence gating off this RFC should be aware the document itself is not internally consistent on this exact constant.

## 5. Recommended composite controller design

The smallest principled upgrade from [Kalman + fixed 350 ms deadband] using the above, in four pieces plus one cross-cutting caution:

**1. Event-triggered threshold with hysteresis and minimum inter-event time (§1a, Eq. 25 + Theorem 1).** Replace the flat `deadband_ms` gate in `policy.h`'s `CorrectionPolicy::on_estimate` with a mixed condition modeled on Donkers & Heemels's Eq. 25: trigger when |error|² exceeds ε² + σ·(scatter or corroboration term)², where ε is the existing `deadband_ms`/`ENGINE_DEADBAND_MS` (kept as a hard floor — §V.C's LMI-feasibility result depends only on the relative term σ, so shrinking σ alone stays provably safe) and σ shrinks as `in_deadband_streak_`/`converged_` persists. Layer NTP's persistence discipline (STEPT+WATCH, Figure 28) on top as a *second*, slower gate: a sub-threshold-but-corroborated residual that persists past a new confirm window (a `PolicyConfig::confirm_window_ns`, separate from `settle_ns`) earns a correction even without crossing the instantaneous threshold. This directly targets failure (i).

**2. An NTP-style sample filter, adapted for step-only actuation (§1b).** Give `estimator.h` an N-stage shift register of recent fixes (mirroring the clock filter's 8-stage register), selected/weighted by per-fix confidence/peak-ratio rather than NTP's round-trip-delay analog, feeding a **computed** measurement variance into the Kalman update instead of the fixed `meas_noise_ms2=25.0`. Adopt the STEP/ADJ *decision structure* (magnitude gate + persistence timer before acting) but explicitly drop the slew branch entirely — we are always in "step" — and scope the STEP consequence down from NTP's full-reset ("all associations MUST be reset") to a targeted reset of only the implicated estimator state, since a full reset is far more perceptually costly for us than for a background clock daemon. This targets failure (i) alongside item 1, and supplies the general shape (not the specific formula) for tightening the existing `latency_adapt_clamp_ms` per the Smith-predictor resonance caution in §3.

**3. A small hypothesis bank for comb ambiguity, gated by PDA/IPDA rules (§1c, Eq. 3.2/3.6 + Mušicki-Evans track existence) — explicitly extending, not duplicating, `research-offset-disambiguation.md` §4 item 3.** That doc already proposed the bank of parallel `SyncEstimator` instances seeded at comb-implied candidate offsets; this research contributes the **formal gating rule** it left unspecified: size each hypothesis's admission gate from its own posterior covariance via the χ²-quantile test (Eq. 3.2) rather than the fixed `outlier_gate_ms=1200.0`, and prune hypotheses using a per-hypothesis existence-probability that decays like `conf_age_tau_s` (mirroring IPDA). **Critical scope limit, per §2(iii)/§4 above: this bank must never be used for the self-match problem** — its measurement model assumes independent, honestly-distributed candidates, which self-match's structured, self-correlated "clutter" violates by construction. This targets failure (ii) only.

**4. Formally-grounded probe scheduling (§1d, Wittenmark's cautious/dual distinction) — extending, not duplicating, `research-offset-disambiguation.md` §2b's active-probe idea.** That doc proposed the buildable mechanism (a known perturbation whose signature only our audio carries) but left its timing informal. This research supplies the trigger: fire the probe when the system has been in Wittenmark's "turn-off" condition — confidence below `min_confidence_to_correct` — for longer than a dwell window **and** no accepted fix has restored it passively in that window. Because probing cost is a discrete, near-fixed penalty rather than the smoothly-scalable cost classical dual control assumes (§3 above), keep this as a rare, binary, gated decision rather than porting any continuous probe-magnitude formula — none of what was retrieved from Wittenmark supports one anyway (§4 item 2). This targets failure (iii), composing with the already-ticketed CTL-01 sentinel rather than replacing it.

**Net:** items 1–2 are the cheapest and most directly buildable, reusing `estimator.h`/`policy.h` state and patterns (`in_deadband_streak_`, `outlier_gate_ms`, `latency_adapt_clamp_ms`) that already exist in a less general form. Item 3 is a real but bounded follow-on, explicitly scoped away from the self-match problem it must not touch. Item 4 is the cheapest to specify (a trigger condition) and the most expensive to build (the probe mechanism itself, per the sibling doc), and is the one place this research changes *when* a planned mechanism fires rather than proposing a new one.
