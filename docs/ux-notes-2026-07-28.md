# UX notes — calibration device test · 2026-07-28

Observations collected from live screenshots during field test 8 (the
calibration device pass). These are **notes for later**, not tickets —
severity-sorted so the next UX pass can triage. Functional defects found the
same day (silent chirp, stale-clock arm, sheet never rendering) were fixed
during the test and are documented in the commits, not here.

## Worth fixing

1. **Off-scale values clamp invisibly on the caliper.** The bogus 2232 ms
   profile drew its settled line pinned at the 600 ms axis edge — the hero
   said 2232 while the scale silently implied ~600. Any value past
   `scaleRangeMs` renders indistinguishably from one *at* the edge. Needs an
   off-scale affordance (clipped-arrow tell, or an axis that stretches),
   especially since a bad measurement is exactly when the visual should look
   wrong.

2. **Raw routeId leaks into user-facing copy.** The gate said "New here:
   speaker", the shelf row and detail title say "speaker" — lowercase
   plumbing vocabulary — while the guided sheet says "Phone speaker" for the
   same route. `CalibrationProfile.deviceName` stores the routeId when
   `routeName` is null. One humanising fallback ("Phone speaker") applied at
   a single point would fix gate, shelf, and detail together.

3. **"Calibrate again" is below the fold.** On a Pixel 10 Pro the detail
   pane's primary action needs a sheet-drag to reach. The partially-expanded
   `ModalBottomSheet` default hides the one thing the pane exists to offer;
   it should open expanded or the content should fit the peek height.

4. **The detail caliper's right axis label clips** — renders "60…" with the
   final digit cut by the recessed well's inset. Label needs padding inside
   the well, or the well needs to account for label width.

## Worth considering

5. **Attempt debounce.** Rapid Try-again taps used to contaminate
   measurements via the stale-clock bug (fixed in core — t0 now comes from
   fresh capture), but the UI still allows starting a new attempt the moment
   the last one fails. A short cooldown, or disabling the pill while the
   previous chirp's audio could still be in the 12 s capture history, would
   remove the residual risk class entirely.

6. **Landscape needs a pass.** The gate rendered correctly in landscape, but
   its primary pill sat at the very bottom edge of the screen. General
   landscape ergonomics were already flagged in ux-audit-2026-07 (#13);
   calibration sheets should be included in that pass.

7. **Single-sample caliper reads as empty.** With one retained sample
   coincident with the settled line (and doubly so when off-scale, see #1),
   the detail well looks blank. The spec's single-tick treatment exists, but
   at 20 dp row height and one tick the visual carries almost nothing —
   worth checking against the populated preview once referee samples
   accumulate in real use.

## Already known / tracked elsewhere

- Debug overlay occupies the top third of every screen (field-phase
  artifact; tap-to-dismiss exists, full removal gated on end of field
  phase — ux-audit-2026-07 #4).
- TalkBack verification of the CFX-03 semantics still needs a device pass

  app's own state, discovered when the chirp played into the user's

## What the screenshots confirmed working

The first-contact gate (route-neutral copy, decline path, re-raise for a
still-unprofiled route), gate-wins sheet precedence, mid-flight route-change
cancellation, the evenhanded Failed copy, the shelf row anatomy (name /
tabular value / provenance qualifier / `· Connected` tell / caliper strip),
the detail hero staying `ink`, recalibration preserving `createdAtMs` while
updating the value, and the full measurement pipeline ending in a plausible
**153 ms MEASURED** phone-speaker profile.

## Live-suite additions (field test 8)

8. **A single fix can drive a large uncorroborated correction that never
   recovers** ('You May Be Right', song 2). The full log shows exactly one
   correction: seek jump 1259 ms on e=−1017 at conf 0.74, eight seconds
   after the aim — then a mic-steady ~848 ms offset with the engine
   believing ~74 ms. The user called it live ("overcorrecting /
   overshooting") while the assistant's first hypothesis (source skew) was
   wrong: raw post-correction errors (215–562 ms) hovered near the 350 ms
   deadband and the filter averaged them down, so the overshoot stood.
   Likely trigger: self-similar intro riffs matching one phrase off.
   Control-loop follow-up: corrections above some size should require a
   corroborating second fix (the self-match guard already has this
   two-fix pattern) or post-seek verification that error actually shrank.
   The referee measured the truth throughout (~848) — with fixed drift
   semantics it would have flagged this session honestly.

9. **Referee drift semantics are wrong in CAL-04's implementation (and the
   spec text that fed it):** drift compares the residual against the
   profile's latencyMs, but the residual IS the error (≈0 when healthy). A
   perfect 43 ms floor reading flagged `drifted=true` on a profile of 153.
   Fix queued: drift = residual > threshold, set AND cleared per committed
   sample. Note the reverb-floor dependence: a 50 ms threshold sits below
   the ~85 ms floor of more reverberant rooms and would flag forever there.

10. **The self-match guard is blind to a room song-change while we play on.**
    When the room moved to the next track, recognition kept matching OUR
    still-playing audio with perfect 1:1 offset continuity — because our own
    playback seamlessly continues the old room timeline, the FT4 guard's
    continuity test passes and arbitration never triggers. The session sat
    "LOCKED" to itself until our track's own end-of-track pause broke the
    loop. The referee is the natural sentinel: while self-matched, its
    windows lose the second copy (invalid / no agreement), so "referee gone
    quiet while LOCKED" is a usable self-match alarm. Control-loop
    follow-up alongside note 8.

11. **Self-match after ANY room discontinuity is the dominant real-world
    failure, proven live.** With the session "LOCKED", a forced room seek
    changed nothing: the next fix (offset 131620, zEnd=81) matched our own
    projected position exactly, not either room timeline. Confirmed from
    four triggers today: room song-change, room stall, room seek, and
    rapid operator taps. In this state the engine self-confirms (~-36 ms),
    the analyzer shows a fake floor once the true offset exceeds its
    2.5 s window, and only the listener knows. The engine itself printed
    the truth (-5396 ms, matching the user's "8 beats") the moment the
    end-of-track pause forced a fresh listen. Fix direction: referee
    validity collapsing while LOCKED as a self-match sentinel, plus
    correction corroboration (note 8) and possibly pausing our own output
    briefly during re-fix windows after continuity breaks.

12. **Testing cadence:** the user is right that most conditions can be
    forced in ~15 seconds (scrubber seeks, leave/rejoin) instead of
    waiting out full tracks — codify in the field-test protocol.

13. **The caliper's tick mapping needs the drift-semantics correction too.**
    Ticks draw refereeSamples on the 0–600 latency axis, but corrected
    referee samples are residual ERRORS (~40 ms when healthy) — they would
    render near zero, far from the settled line, implying disagreement
    during perfect sync. The right mapping is `latencyMs + residual`:
    healthy ticks then land ON the settled line and drift visibly scatters
    away from it, which restores the original visual metaphor exactly.
    (Promoted trims no longer enter the ring at all — they are latency
    values, not errors.)
